DayNote 0.1.2 修复数据目录切换和开机自启的问题。

- 在设置页保存新数据目录后，重启 DayNote 之前所有入口（应用、HTTP、CLI、MCP）继续使用当前目录，不再出现一部分写新目录、一部分写原目录的情况。重启时才切换；已在运行的 MCP 服务会在下一次调用时自动跟上，不需要重启 MCP 客户端。
- 选择数据目录时只做只读检查，不再升级或新建其中的数据库；升级只在 DayNote 切换到该目录启动时进行。
- 数据目录配置损坏或目录无法打开时，弹出“DayNote 无法启动”提示，说明原因、相关文件路径和处理办法，不再无提示退出；不会自动改用其他目录。
- 开机自启只属于它启动的那份程序：电脑上有多份 DayNote 时不再互相抢占，“开机自启”开关只在自启指向当前程序时显示为开启。

从 0.1.1 升级：在应用内确认更新即可，沿用原安装目录和数据目录。从 0.1.0 升级：需要从本 Release 下载 `DayNote-0.1.2-windows-x64-setup.exe` 手动安装一次。

本版本没有数据库结构变更。有待生效的新目录时，`location.json` 会暂时写成包含 `current` 和 `pending` 的对象，0.1.1 及更早版本无法读取这种写法；重启一次 0.1.2 或在设置页重新选择当前目录后恢复为原格式。更新前建议退出正在占用 CLI/MCP 可执行文件的外部客户端。Windows x64；尚无 Windows Authenticode 代码签名，可能出现未知发布者提示。
