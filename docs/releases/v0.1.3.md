DayNote 0.1.3 新增所有会话共用的本地 MCP 服务，减少后台常驻进程。

- 在 DayNote 现有本地服务中提供 Streamable HTTP MCP：默认地址为 `http://127.0.0.1:47821/mcp`。Codex、Claude Code 和其他兼容客户端连接同一地址，共用一个 DayNote 进程及同一份数据，不再需要为每个会话启动 `daynote-cli.exe mcp`。
- 设置页优先展示共享 MCP 地址、实际运行状态和令牌文件位置。端口修改、服务开关和令牌重置同时作用于 MCP 与原有 REST API；`/v1` 接口保持兼容。
- 保留旧版 stdio MCP 入口。现有客户端配置不会由安装器擅自修改；请按 [AI 接口配置文档](https://github.com/Scandinavian0/daynote/blob/v0.1.3/docs/AI-%E6%8E%A5%E5%8F%A3%E8%AF%B4%E6%98%8E.md) 将启动命令改为 HTTP 地址，并配置 Bearer 令牌。完成迁移后重启客户端，旧的 CLI 会话才会退出。
- 共享服务只监听本机回环地址，保留令牌、Host/Origin 检查、请求大小、超时和并发限制。不同客户端的请求来源分别处理，写入仍会更新桌面界面。

共享模式需要 DayNote 保持运行；关闭主窗口后仍可在托盘运行，选择“退出应用”会停止服务。可以按需在设置中开启开机自启。修改端口或重置令牌后，需要同步修改客户端配置并重新连接。

本版本没有数据库结构变更，升级沿用原安装目录、数据目录和访问令牌，并创建桌面快捷方式。0.1.1/0.1.2 可通过应用内更新安装；0.1.0 用户请下载安装包手动升级。安装前请退出旧版应用和占用其 CLI 的客户端。

Windows x64。更新包带 DayNote 更新器验证签名；尚无 Windows Authenticode 代码签名。此前版本曾触发卡巴斯基检测，本次 MCP 进程修复不代表杀毒厂商已撤销检测。
