# 安装、升级和数据目录

## 安装

从项目 Release 下载 `DayNote-0.1.3-windows-x64-setup.exe`。安装器支持简体中文和英文，默认仅为当前用户安装，创建桌面及开始菜单快捷方式。

Windows WebView2 Runtime 缺失时安装器会联网安装。当前安装器没有 Windows Authenticode 发布者签名；下载来源及校验值应与项目 Release 一致。

从 0.1.1 起支持应用内更新：新版本提示出现后选择“下载并安装”，或在设置中手动检查。0.1.0 用户先手动安装一次新版。安装版覆盖升级沿用原目录并保留数据，不需要重复搬迁。详见 [更新说明](UPDATES.md)。安装器尚无 Windows 发布者签名，应用内更新包另有独立签名用于校验来源。

## 数据目录优先级

1. 非空环境变量 `DAYNOTE_DATA_DIR`。
2. 设置页保存并已生效的目录，配置文件位于 `%LOCALAPPDATA%\DayNoteData\location.json`。刚保存、尚未重启 DayNote 的新目录不参与这里的判断。
3. 程序所在目录已有 `data\daynote.db`，或存在 `portable.txt` 标记：使用程序旁的 `data`。
4. 新安装使用 `%LOCALAPPDATA%\DayNoteData`，与默认程序安装目录 `%LOCALAPPDATA%\DayNote` 分开。

设置页会显示实际目录。任务和设置在 `daynote.db`；共享 MCP / REST 的访问令牌在 `api-token.txt`。程序不会把数据库或令牌包含在安装包中。

## 从旧版迁移到安装版

1. 在旧版设置页记下数据目录，然后从托盘或设置页退出 DayNote；同时停止所有连接 DayNote 的 MCP/CLI 客户端。
2. 将整个旧数据目录备份到其他位置。SQLite 运行时可能存在 `daynote.db-wal` / `daynote.db-shm`，停止所有读写进程后再备份和复制。
3. 安装新版。首次启动前，把备份目录中的文件复制到 `%LOCALAPPDATA%\DayNoteData`。目标已有数据时先备份，不要直接合并两个数据库。
4. 启动新版，核对设置页数据目录与已有任务。
5. 按新版设置页显示的共享 MCP 地址和令牌文件配置客户端，具体示例见 [AI 接口说明](AI-接口说明.md)。使用旧版 stdio 时，按实际安装位置更新命令路径。

也可以让 GUI 和 MCP 客户端都使用同一个 `DAYNOTE_DATA_DIR`，继续访问已有目录；环境变量更改后需要重启程序和 MCP 客户端。

## 升级已有 MCP 配置

共享 MCP 使用现有的数据库和令牌文件，升级不要求搬迁数据。安装升级不会自动改写 Codex、Claude Code 或其他客户端的配置；原来的 `daynote-cli.exe mcp` stdio 配置继续可用，但每个聊天仍会启动独立的常驻 CLI。

改用共享服务时，先启动 DayNote，在设置 → AI 接口确认服务正在监听，再把原有的 stdio 定义替换为 `/mcp` URL 和 Bearer 请求头配置，最后重新连接或重启客户端。不要同时保留同名 stdio 与 HTTP 定义。多个聊天会共用同一个桌面应用提供的服务。关闭窗口后 DayNote 仍驻留托盘；完全退出 DayNote 会停止共享服务。配置示例见 [AI 接口说明](AI-接口说明.md)。

## 修改 HTTP 端口

进入设置 → AI 接口，在 HTTP 端口输入框填写 `1024–65535` 的整数，点击保存。地址固定为本机 `127.0.0.1`，不会监听局域网。MCP 与 REST 共用开关和端口；修改后更新客户端使用的 `/mcp` 或 `/v1` URL，并重新连接。兼容 MCP stdio 不受端口变化影响。

HTTP 开关关闭时仍可保存下次启用使用的端口。若端口被占用，应用保留原有服务并显示错误。令牌路径由数据目录确定；不能把任意字符串路径当成访问令牌。

## 更改目录与重新生成令牌

数据目录输入框支持绝对路径。保存前会检查目录能否创建和写入；目录里已有 `daynote.db` 时，以只读方式确认它是本程序能打开的数据库版本。**检查不会升级或改动所选目录里的数据库**，目录里没有数据库时也不会新建；仍在使用该目录的旧版程序不受影响。数据库升级只在 DayNote 真正切换到该目录启动时发生。

保存后、重启 DayNote 之前，应用、HTTP 接口、CLI 和 MCP 都继续使用当前目录，设置页会提示“已选择新目录，重启 DayNote 后生效”。重启 DayNote 时才切换到新目录；共享 MCP 客户端需重新连接，并使用新目录中 `api-token.txt` 的令牌。兼容 stdio 服务会在下一次调用时自动跟上目录。若重启时新目录已不可用（例如磁盘未连接，或其中的数据库来自更新的版本），DayNote 继续使用原目录，并在设置页以错误提示说明原因。重新选择当前正在使用的目录，可取消尚未生效的选择。

**切换不自动搬迁或合并数据，原目录会保留。** 若想迁移已有任务，请先退出所有读写进程并备份，将数据复制到目标目录，再选择该目录并重启 DayNote。使用 `DAYNOTE_DATA_DIR` 时应修改该环境变量并重启 DayNote 和 MCP 客户端，设置页不能覆盖它。

## 启动失败

数据目录配置损坏、或配置的目录无法打开时，DayNote 不会悄悄改用其他目录（那样会把数据分成两份），而是弹出“DayNote 无法启动”提示，写明原因、涉及的配置文件或数据目录，然后退出。处理办法：

- 配置文件 `location.json` 损坏：关闭提示后删除或修正该文件，再启动 DayNote。删除后使用默认目录；原来目录中的数据不会被删除，之后可在设置页重新选择。
- 数据目录无法打开：确认目录所在磁盘已连接、有写入权限、数据库没有被其他程序占用后重新启动。若要改用其他目录，按提示删除或修正 `location.json`；目录由 `DAYNOTE_DATA_DIR` 指定时，修改或删除该环境变量。

重新生成访问令牌会让旧令牌立即失效，共享 MCP 与 REST 客户端都需要重新读取 `api-token.txt`、更新配置并重新连接或重启客户端。文件路径不是令牌，客户端需要使用文件中的内容。兼容 MCP stdio 不使用该令牌。令牌文件路径随实际数据目录变化。

## 备份与卸载

退出 GUI，并停止所有 MCP/CLI 读写进程后备份整个数据目录。卸载只移除程序和快捷方式，保留备忘数据。确实需要清空时，请先确认设置页显示的数据目录并自行备份。

首次运行发布版会启用开机启动，可在设置中关闭。开机自启只属于最后一次由用户开启它的那份程序：电脑上同时有安装版和便携副本时，首次运行的副本若发现自启已指向另一份程序，不会抢过来；启动时也不会改写指向其他程序的自启项。设置页和托盘的“开机自启”只在自启指向当前这份程序时显示为开启；在这里开启会把自启改为当前程序，关闭只移除指向当前程序的自启项。应用关闭窗口时仍驻留托盘；完全退出请使用托盘“退出”或设置页的“退出应用”。
