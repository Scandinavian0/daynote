# 提醒窗口的透明遮挡问题

## 已确认的故障状态

在 Windows 实机上，提醒根窗口仍位于屏幕右下角并接收鼠标命中，页面 DOM 和无障碍树包含正常卡片，但 WebView2 的 `Intermediate D3D Window` 位于屏幕原点，完全离开其直接父窗口客户区。结果是内容不可见，外层窗口继续遮挡桌面。

对隔离运行的旧版注入同一子窗口位移可以重现透明卡片。将外层窗口改变一像素再恢复，不能让绘制子窗口归位；只把绘制子窗口放回父客户区原点后，实屏恢复。20 次普通冷启动未重现最初错位，因此不能把初始离屏位置或 GPU 进程重启称为已证实的初始诱因。

## 修复范围

显示提醒后及现有每秒 watcher 检查时，`reminder_surface` 仅检查本进程的可见提醒根窗口，沿后代关系匹配已知的 Chromium 绘制窗口及直接父类。只有绘制面不小于视口、且两者完全不相交时，才异步将绘制面移回父客户区 `(0, 0)`。绘制面可能大于视口，因此不以尺寸相等作为前提。

该操作不改变大小、Z 序、焦点，不含显示窗口标志；隐藏的提醒不会被 watcher 重新打开。正常相交的绘制面不被移动。未知窗口类或层次直接跳过。它依赖 Chromium 的窗口类名称；未来 WebView2 实现变更需要重新验收。这不是对所有显卡、驱动或透明窗口故障的通用修复，也不改变系统图形或安全设置。

页面在事件注册完成后读取队列，注册失败仍尝试初次读取；过期读取不能覆盖新结果。空队列高度为零，初始高度也为零。高度写入只保留一个在途请求和最新待写高度，避免旧的零高度晚到而隐藏新卡片。内容和“稍后”选项的变化均更新高度。

## 回归方法

`npm test` 运行真实 Svelte 组件，模拟事件注册中的队列变化、读取乱序、旧高度延迟及稍后选项换行。这些测试只替换原生 IPC 边界。

Windows 实机验收需使用隔离 Tauri identifier、数据目录、WebView2 profile、HTTP 端口和快捷键的构建，不要用用户正在运行的程序做故障注入。例如先通过额外配置将 identifier 设置为 `local.daynote.reminder-probe`，在独立目录运行编译产物，在该测试数据中创建一条到期提醒，然后执行：

```powershell
python scripts/verify-reminder-surface.py --pid <测试进程ID> --expected-exe '<隔离目录>\DayNote.exe' --rounds 10
```

脚本核对进程路径，先确认观察到注入的子窗口坐标，再等待恢复，并检查外层位置/尺寸及前台焦点保持不变。它不读取任务正文或令牌。旧版应报 `invisible input-blocking reminder did not recover`，修复版应全部通过。若故障未被观测到则报未验证，不计通过；禁止 `python -O` 和零轮测试。测试期间不要切换前台窗口，否则焦点结果会受外部输入干扰。

还需通过实际桌面截图和点击确认画面、稍后选项和关闭行为；原生坐标通过不能代替视觉验收。关闭最后一张卡片后检查根窗口隐藏，跨过若干 watcher 周期仍隐藏，原位置不再命中 DayNote。实际重启电脑、长时间运行及其他显示器/驱动需要分别说明验证情况。
